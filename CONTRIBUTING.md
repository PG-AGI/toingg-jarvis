# Contributing to Toingg Jarvis

Thank you for your interest in contributing to Toingg Jarvis.

We welcome contributions of all sizes, from documentation fixes to major features.

---

## Ways to Contribute

- Report bugs
- Suggest features
- Improve documentation
- Add tests
- Fix issues
- Review pull requests

---

## Getting Started

### 1. Fork the Repository

Create your own fork of the project.

### 2. Clone Your Fork

```bash
git clone https://github.com/YOUR_USERNAME/toingg-jarvis.git
cd toingg-jarvis
```

### 3. Create a Branch

```bash
git checkout -b feature/my-change
```

### 4. Make Changes

Write clean, well-tested code.

### 5. Commit Changes

```bash
git commit -m "feat: add wake word configuration"
```

### 6. Push to Your Fork

```bash
git push origin feature/my-change
```

### 7. Open a Pull Request

Submit a pull request to the `main` branch.

---

## Branch Naming Convention

- `feature/short-description`
- `fix/short-description`
- `docs/short-description`
- `test/short-description`

---

## Commit Message Convention

We recommend Conventional Commits:

- `feat:`
- `fix:`
- `docs:`
- `test:`
- `refactor:`
- `chore:`

Examples:

- `feat: add OpenAI provider`
- `fix: resolve audio initialization issue`
- `docs: improve installation guide`

---

## Coding Guidelines

- Keep changes focused and minimal.
- Write clear and maintainable code.
- Add tests when applicable.
- Update documentation for user-facing changes.
- Avoid unrelated formatting changes.

---

## Pull Request Checklist

Before submitting, ensure:

- [ ] Code builds successfully
- [ ] Tests pass
- [ ] Documentation updated if needed
- [ ] No sensitive data included
- [ ] PR description explains the change

---

## Good First Issues

Look for issues labeled:

- `good first issue`
- `help wanted`
- `documentation`

---

## Contributor Rewards

Merged pull requests may earn points.

- 1 point = ₹1
- Minimum redemption = 1,000 points

Point awards depend on complexity, impact, and quality.

See `REWARD_SYSTEM.md` for details.

---

## Review Process

Maintainers will review your pull request and may request changes.

Please be patient and responsive to feedback.

## Questions
